# Dive_searcher

毎朝 8:00 (JST) に、その日に **先着販売** が始まるチケットを TicketDive と LivePocket から集め、Discord に通知します。
抽選と、除外語を含むものは対象外です。除外語は `main.py` で変更できます。

- `EXCLUDE_KEYWORDS`: イベント名・受付名のどちらかに含むと除外（当日券、撮影会、トークショー、オフ会 など）
- `EXCLUDE_TITLE_KEYWORDS`: イベント名に含むと除外（事前予約）

Discord のフォーラムチャンネルに、毎日「MM/DD 本日のチケ発情報」という投稿を 1 つ作り、
発売時刻ごと・プレイガイドごとに **1イベント1メッセージ** で並べます。
スマホでもメッセージを長押し →「テキストをコピー」で、そのイベントだけをコピーできます。

```
10/30 本日のチケ発情報
```
```
10時00分
ライブポケット
```
```
イベント名:○○
URL:https://livepocket.jp/e/...
```
```
チケットダイブ
```
```
イベント名:○○
URL:https://ticketdive.com/event/...
```
```
-------------------------------
21時15分
チケットダイブ
```

Webhook が通常のテキストチャンネルのものでも、投稿を作らずにチャンネルへ同じ内容を送ります。

| サイト | 状態 |
| --- | --- |
| TicketDive | 対応済み |
| LivePocket | 対応済み |

## セットアップ

1. Discord でフォーラムチャンネルを作り、そのチャンネルの設定 → 連携サービス → ウェブフック で Webhook URL を作成
2. このリポジトリの Settings → Secrets and variables → Actions → New repository secret
   - Name: `DISCORD_WEBHOOK_URL`
   - Secret: 1 の URL
3. Actions タブ → 「本日発売チケット通知」→ Run workflow で動作確認
   （手動実行は 8:00 JST より前なら 8:00 まで待ち、それ以外はすぐ送信します）

## ローカルで試す

```bash
python main.py collect livepocket lp.json
python main.py collect ticketdive td.json
python main.py send --dry-run lp.json td.json
```

`send` に `--dry-run` を付けるか `DISCORD_WEBHOOK_URL` が未設定なら、Discord には送らず標準出力に表示します。

## 仕組み

GitHub Actions で 5:07 JST に起動し、サイトごとに並行して 30〜90 分かけて収集したあと、結果を 1 つにまとめて 8:00 JST に送信します。
取得に失敗したサイトがあれば、投稿の先頭にその旨を表示します。
GitHub のスケジュール実行は遅れることがあるため、前倒ししています。
起動が 8:00 を過ぎた場合は、収集が終わり次第送信します。

### TicketDive
TicketDive には全イベント一覧がなく、検索は 1 回最大 20 件・並び順固定・ページ送りなしです。
そこで以下でイベントを集め、各イベントページの受付情報（`startApply`）が今日のものを抽出します。

- トップページ（受付中・カルーセル）
- 1 文字検索と、20 件で打ち切られた検索ワードを見つかったタイトル中で前後に伸ばした再検索（最大 800 回）

イベントごとの受付情報は `state/ticketdive.json` に保存し、Actions のキャッシュ（サイトごと）で次回に引き継ぎます。
受付前・状態が変わったイベントは毎回、それ以外は 2 日ごとに詳細ページを取り直します。

制約:
- 検索に引っかからないイベントは取りこぼす可能性があります
- 8:00 以降に公開され、同じ日に受付開始する受付は通知できません

### LivePocket
新しい LivePocket（https://livepocket.jp ）を対象にしています（旧サイト t.livepocket.jp は 2026/10/21 に閉鎖）。

- 検索結果（開催日順・20 件ずつ）に開催前・開催中のイベントがすべて並ぶので、全ページ（約 450 ページ）をたどってイベントを集める
- 各イベントページの「受付・チケット情報」から、受付ごとの方式（先着/抽選）と販売受付期間の開始日時を読む
- 受付情報は `state/livepocket.json` に保存して使い回す。詳細ページを取り直すのは、新しいイベント・販売状態が変わったもの・
  今日明日に受付が始まるもの・保存から日数が経ったもの（販売前は 3 日、それ以外は 7 日）
- 1 回の詳細ページ取得は最大 2,500 件。イベントが約 9,000 件あるため、初回から数日は受付情報がそろわず取りこぼしがあります
